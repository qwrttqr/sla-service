# SLA Dispatcher — Frontend

Веб-интерфейс диспетчера для планирования выездных инженеров, контроля окон прибытия и соблюдения SLA.

---

## 🚀 Быстрый старт

### Требования
- **Node.js**: версии `18.x` или новее (`20.x` рекомендуется)
- **Пакетный менеджер**: `npm`, `pnpm` или `yarn`

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск в режиме разработки
```bash
npm run dev
```
После запуска интерфейс будет доступен по адресу:  
👉 **[http://localhost:3000](http://localhost:3000)**

---

## ⚡ Режимы работы

### 🟢 1. С подключением к бэкенду (FastAPI + OR-Tools)
Если запущен локальный бэкенд на порту `8888` (например, через Docker):
* В шапке загорится зелёный индикатор **«Бэкенд онлайн»**.
* Запросы к `/api` автоматически проксируются Vite на `http://localhost:8888`.
* При загрузке CSV файлов расчёт расписания и оптимизация маршрутов выполняются реальным движком OR-Tools.

### 🟡 2. Автономный режим (Демо / Офлайн)
Бэкенд **не обязателен** для тестирования и презентации интерфейса:
* Нажмите кнопку **«Демо»** в шапке — приложение загрузит демонстрационные данные и отобразит готовый план визитов, временную шкалу и карту.
* В папке `public/` лежат готовые тестовые датасеты:
  * `public/engineers.csv` — смена, локация офиса, транспорт и навыки инженеров.
  * `public/requests.csv` — список заявок с адресами в Москве, окнами SLA и типами работ.
* Фронтенд содержит встроенную офлайн-базу геокоординат (`addressCache.json`), поэтому московские адреса на карте отображаются точно без внешних запросов к геокодерам.

## ⚙️ Настройка прокси (при смене порта бэкенда)

Если ваш бэкенд запущен на другом порту или адресе, отредактируйте `proxy` в файле **`vite.config.js`**:
```js
proxy: {
  '/api': {
    target: 'http://localhost:8888', // Укажите ваш хост бэкенда
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/api/, '')
  }
}
```
